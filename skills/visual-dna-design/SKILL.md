# Visual DNA · 通用前端视觉设计与布局系统

## 技能定位

把 AI 从“套一个后台模板”变成“先理解业务，再设计信息结构与视觉身份”的前端设计伙伴。技能适用于已有应用改造，也适用于新应用设计；不要求每个项目采用相同配色或相同布局，而是要求每个项目有清晰、可解释、可定制的视觉语言。

核心原则：**业务决定结构，视觉风格决定表达，配色主题决定色彩；三者可以独立调整，不得绑成一套不可拆分的模板。**

## 1. 什么时候使用

当用户要求开发或改造网站、后台、数据看板、SaaS、AI 工具、内容平台、知识图谱、运营控制台、学习工具或移动端 Web 应用时使用。特别适用于以下问题：

- 页面像 AI 默认生成的后台，多个产品都长得一样。
- 默认科技蓝紫、深色侧栏、四张 KPI 卡、左右双栏反复出现。
- 内容区域被固定最大宽度限制，宽屏仍有大量空白。
- 同一行卡片高度不一致、底边错位、空状态导致布局不协调。
- 用户需要自定义主题、布局、导航位置、收起状态和字体。
- 需要将视觉设计能力复用到多个代码仓库或不同技术栈。

## 2. 强制执行工作流

### 第一步：先审计，不要先换皮

1. 检查项目框架、页面入口、组件、CSS 组织、路由、设计 Token、主题持久化方式和现有测试。
2. 找出页面的核心任务、主要内容、次要信息、后台状态和用户最常操作的区域。
3. 区分用户看板里的“业务信息”与“系统诊断信息”。运行环境、调试信息、隐私/执行模式、内部计数等默认属于设置页或详情区，除非业务确实需要将它们放在首屏。
4. 标记必须保持不变的页面、DOM 锚点、行为、API 契约、多端预览与既有测试。只修改用户授权范围。
5. 不要仅凭截图推断代码结构。不要删除功能来换取更漂亮的静态页面。

### 第二步：定义 Visual DNA

每个项目至少确定以下项目，再开始写样式：

- 业务角色：报告、探索画布、监控控制台、运营工具、内容阅读、工作流或其他。
- 视觉性格：编辑式、专业商务、自然、工业、数据密集、创意或品牌表达。
- 信息密度：低、中、高；用来决定留白、行高、模块数量和表格表现。
- 布局模式：六种预设之一或经用户确认的专属结构。
- 配色主题：从主题预设起步，允许用户逐项微调。
- 字体层级：中英文、标题、正文、数字、代码各自使用合理的字体栈。
- 响应式策略：桌面、平板、手机的断点和导航变形规则。

禁止把“高级、现代、简洁”当作完整设计需求。应把这些词翻译为具体的颜色、字号、间距、信息层级、布局和交互规则。

### 第三步：遵循反模板化规则

以下模式不是绝对禁止，但不能无条件作为每个项目的默认答案：

- 深色左侧导航 + 浅灰蓝背景。
- 顶部四张相同 KPI 卡。
- 全部内容被白色圆角卡片包围。
- 亮蓝主按钮 + 淡紫图标。
- 每块内容都加图标、渐变、发光、装饰线或无意义统计数字。
- 为了“高级”使用过多留白，使核心任务只能占页面的一小部分。
- 所有页面都使用相同的双栏布局，不考虑信息之间的关系。

应通过排版、比例、模块组合、字体、颜色、图表和交互状态建立辨识度。克制并不等于空白；信息密度高也不等于拥挤。

## 3. 页面内容满铺规则：目标使用至少 90% 可用宽度

对工作台、看板、控制台和数据工具，默认让主内容充分利用可用画布。内容区目标为**导航区域扣除后的可用主区域宽度的 90% 以上**。

- 不要默认使用固定的 1200px、1360px 或 1480px 最大宽度。
- 主内容容器优先使用 width: 100% 与 max-width: none。
- 左右只保留随视口缩放的必要内边距，例如 clamp(14px, 2.5vw, 44px)。
- 侧栏导航占据的空间应通过布局或主内容 margin 正确扣除，不得让主内容覆盖导航。
- 阅读型文章、长文档和纯营销落地页可以使用较窄阅读列；此例外应由阅读体验决定，不套用到整个工作台。
- 内容区“满铺”不代表每个模块都铺满整行。网格仍要根据内容关系划分列宽。
- 对超宽屏做实际测量，检查主内容宽度、左右边距、导航占位和横向溢出。

建议起步 CSS：

    .vd-main {
      min-width: 0;
      padding: 24px clamp(14px, 2.5vw, 44px) 38px;
    }
    .vd-main-inner {
      width: 100%;
      max-width: none;
      margin-inline: auto;
    }

## 4. 六种可复用页面布局

每个布局必须改变内容模块的结构关系，而不只是换颜色。建议将主要模块标记为 primary、task、result、capability，并在 CSS 中按布局调整其网格位置。

| 布局名 | 技术值 | 结构规则 | 适用场景 |
|---|---|---|---|
| 编辑式布局 | editorial | 主任务通栏；任务状态与成果并排；能力说明位于下方 | 通用工作台、分析工具 |
| 平衡网格 | balanced | 四个主模块以 2×2 网格组织 | 管理看板、模块重要性接近的工具 |
| 纵向流程 | vertical | 单列，自上而下按任务顺序阅读 | 移动优先、向导、教学与配置流程 |
| 分析聚焦 | compact | 主分析区更宽，任务状态与结果位于次级栏 | 分析工作台、数据工具 |
| Bento 拼贴 | bento | 大型主模块搭配不同跨度的辅助模块 | 创意工具、AI 工作台、项目总览 |
| 左右分栏 | split | 左右分区分别承载不同类型的模块 | 主操作与辅助信息需要并列的应用 |

布局切换必须做到：

1. 用户选择后立即生效。
2. 保存布局及其用户可调参数，刷新后恢复。
3. 每种布局都定义桌面、平板与手机的降级规则。
4. 切换布局不清空业务数据、不重置主题颜色、不改变 API 行为。
5. 宽屏下避免模块被不必要地固定为相同窄列；窄屏下则必须主动退化为单列或可读的双列。

## 5. 导航的六种位置与收起策略

支持以下导航模式，并为每种模式定义真实的交互，而不是仅修改外观：

| 导航模式 | 技术值 | 行为要求 |
|---|---|---|
| 顶部 | top | 横向导航，不遮挡主标题与操作按钮 |
| 左侧 | left | 固定或粘性侧栏；主内容正确扣除导航宽度 |
| 右侧 | right | 侧栏位于右侧；主内容正确扣除导航宽度 |
| 底部 | bottom | 固定底栏，移动端适合快捷入口；主内容预留底部安全距离 |
| 悬浮 | floating | 以图标快捷入口为主；必须有标题、Tooltip 或可访问名称 |
| 隐藏 | hidden | 默认隐藏，但必须保留明显、可访问的打开按钮；打开后能关闭、点击导航项后可收起，Esc 可退出 |

同时支持导航收起与展开：

- 左右侧导航收起后保留图标入口，不可以让用户失去导航能力。
- 顶部导航收起后隐藏品牌/文字等次要部分，但保留清晰的展开入口。
- 底部导航在手机上不应挤成不可点击的小目标。
- 隐藏导航不能仅通过 hover 才能打开；触屏和键盘用户必须能操作。
- 导航位置、收起状态与布局选择分别存储，不能因为换布局而意外覆盖另一项设置。
- 左右侧栏不能遮盖内容；在窄屏下要改为顶部区域、抽屉或其他适用模式。

## 6. 卡片、网格与对齐：禁止底边错位

对同一网格行的卡片：

- 网格容器使用 align-items: stretch。
- 卡片外壳使用 min-width: 0、display: flex、flex-direction: column、align-self: stretch。
- 空状态或可伸展的卡片主体可使用 flex: 1。
- 不要通过无条件 height: 100% 强行拉伸卡片；它可能引起高度过度扩张。
- 不同卡片的标题、工具按钮和内容区需要定义一致的内边距、标题行结构与边框规则。
- 有真实日志、表格或成果时，不得因为等高设计而裁切内容。只在内部区域需要滚动时设置明确的 max-height/overflow。
- 图表、表格、弹窗、下拉菜单、长文本、状态徽标和空状态都需要验证。

示例：

    .vd-workspace-grid {
      display: grid;
      align-items: stretch;
      gap: var(--vd-gap, 22px);
      grid-template-columns: repeat(2, minmax(0, 1fr));
    }
    .vd-module {
      min-width: 0;
      display: flex;
      flex-direction: column;
      align-self: stretch;
    }
    .vd-module__panel {
      min-width: 0;
      display: flex;
      flex-direction: column;
      flex: 1 1 auto;
    }
    .vd-empty-state {
      flex: 1 1 auto;
    }

## 7. 高级配色：主题与自定义 Token 分离

建议使用六类可替换主题作为起点：

1. Editorial Chalk / 纸感编辑：暖纸白、森林绿、陶土强调色。
2. Graphite Lime / 石墨荧光：深石墨、酸橙绿，适合监控和技术控制台。
3. Ocean Mist / 海雾青绿：雾青、深海绿，适合探索、自然和产品工具。
4. Midnight Cyan / 午夜青蓝：午夜蓝黑、冰川青，适合深色数据产品。
5. Terracotta / 陶土暖调：亚麻白、陶土红棕，适合内容、生活和教育。
6. Classic Blue / 经典蓝紫：作为兼容主题，而不是所有新项目的唯一默认选项。

每套主题必须一并定义：页面背景、内容表面、主文字、次级文字、边框、主强调色、辅助色、导航底色、输入控件、焦点环、阴影、圆角和状态色。不要只修改背景与主按钮。

自定义颜色控件至少包括：

- 页面背景色。
- 面板底色。
- 主文字色。
- 次级文字色。
- 边框/分割线色。
- 强调色。
- 导航底色。

自定义后即时预览；将主题名与自定义 Token 分开保存；恢复主题预设不能清空用户保存的布局、导航与字体设置。颜色需有对比度检查，成功/警告/错误状态不能只靠颜色区分，必须配合文字或图标。

## 8. 字体选择系统

字体应当按中英文、标题、正文、代码角色选择，而非只在全站随机替换 font-family。

英文字体主选项：

- Inter：UI / 正文默认。
- Source Sans 3：长文阅读。
- DM Sans：产品页 / 营销页。
- Space Grotesk：现代标题。
- Playfair Display：编辑式衬线标题。
- Manrope：SaaS UI。
- Plus Jakarta Sans：品牌 / SaaS。
- JetBrains Mono：代码 / 技术小字。

兼容选项：

- Arial 兼容：Liberation Sans + Arial 系统回退。
- Times 兼容：Liberation Serif + Times New Roman 系统回退。
- 不下载或打包 Microsoft Arial、Times New Roman 文件。

中文字体选项：

- Noto Sans SC：正文 / UI。
- Noto Serif SC：编辑 / 宋体风格。
- LXGW WenKai：文艺排版。
- Smiley Sans：潮流标题。
- Alibaba PuHuiTi：数据 / 后台。
- ZCOOL KuaiLe：圆润标题。
- YouShe BiaoTiHei：Banner / 强标题。
- Chiron GoRound TC：圆润品牌标题，须注意繁体覆盖偏向。

字体设置应支持英文字体、中文字体分别选择、实时预览、保存与恢复默认值。不要谎称所有字体资源已经自托管：需实际核实字体文件、许可证、请求成功与字形覆盖。

混合中英文页面的中文字体栈按项目要求放在前面；对需要严格维持英文品牌字形的标题、代码、SKU 或编号，应给元素单独使用英文栈，以免中文字体的拉丁字形抢先命中。

中文 Web 字体必须控制体积。推荐在 Vite / Webpack / CI 构建阶段按授权允许的范围生成 WOFF2 子集，并覆盖实际 UI 字符、简繁中文、数字、货币、中文标点、全角/半角符号、箭头及动态错误文案。不能只按首页标题做极窄子集。对非 OFL 字体，需核对厂商对自托管、改格式、子集化和再分发的条款；授权不清楚就不自动转码或打包。

字体更完整的表格、CSS @font-face、Tailwind extend.fontFamily、预加载与 crossorigin 方案见 references/typography-fonts.md。

## 9. 用户设置持久化

以下设置需要分别保存并在页面重新打开后恢复：

- 主题和用户自定义颜色。
- 页面布局和列宽/模块间距。
- 导航位置和收起状态。
- 英文字体与中文字体。

推荐使用带版本号的设置键，例如 visual-dna:v1。读取 localStorage 时必须容错：隐私模式、浏览器限制或 JSON 数据损坏不能导致页面崩溃。为未来新增字段预留默认值；不要因为一次版本升级就丢失旧设置。提供“恢复当前类别默认值”，不要让字体重置顺带清空主题与布局。

## 10. 响应式与可访问性

- 桌面：利用宽屏；内容区至少占可用主画布的 90%，根据业务组合两列或多列。
- 平板：默认将复杂的三列/紧凑模式收敛为单列或易读的两列；侧栏不得挤压内容。
- 手机：单列优先；减少页面左右留白；底部导航预留安全区域；悬浮按钮不覆盖主要操作；隐藏导航提供明确唤出方式。
- 输入控件、按钮和导航需要键盘可达、focus-visible 状态和可访问名称。
- 尊重 prefers-reduced-motion。
- 避免只通过颜色表达状态；检查高对比度与字体缩放。
- 避免横向滚动条、遮挡、卡片被裁切、下拉菜单跑出视口和工具栏挤压。

## 11. 给其他应用的 Agent 执行指令模板

当技能被触发时，Agent 应按以下顺序交付：

1. 审计现有代码与冻结基线；明确本次修改范围。
2. 给出业务信息层级与 Visual DNA 方案，说明为什么选择特定布局与配色。
3. 实现可用的主题 Token、六种布局、导航位置与收起、字体选项和本地持久化；如果某项与目标应用不相关，可说明原因并保持不增加。
4. 保留原有 API、状态、数据模型和已有功能，不用假数据填充页面。
5. 在桌面/平板/手机上实际验证布局；测量主内容宽度和并列卡片底边。
6. 运行项目已有测试与新增回归测试。
7. 提供修改文件、验收结果、未完成的资源依赖及真实部署状态。未实际部署不得声称上线。

实施时必须逐项核对 references/acceptance-checklist.md；该清单是发布前质量门禁，不是可选建议。

## 12. 交付验收清单

- [ ] 首屏聚焦主要业务任务；后台运行指标放入设置或系统详情。
- [ ] 视觉语言依据业务决定，不是默认蓝紫模板。
- [ ] 页面主题可以选择、定制、即时预览和持久化。
- [ ] 六种布局对应不同的信息结构，且可以实际切换。
- [ ] 六种导航模式都有正确的键盘、触屏与收起/展开行为。
- [ ] 工作台主内容占可用画布宽度至少 90%，没有固定最大宽度造成的异常大空白。
- [ ] 同一网格行卡片顶部和底部对齐，没有强制 height:100% 导致的过度拉伸。
- [ ] 桌面、平板、手机均没有横向溢出、遮挡和不可操作控件。
- [ ] 中英文、标题、代码的字体角色明确；许可证、文件与字形覆盖经过验证。
- [ ] 设置保存与恢复互相独立，并在存储失败时安全回退。
- [ ] 原有业务功能、数据、API、多平台预览和冻结页面未被无授权改动。
- [ ] 语法、单元/集成、响应式与视觉验收都有真实记录。

**完成定义：** 只有当用户能够实际切换设置、页面在目标视口渲染正确、测试通过且资源/部署状态被诚实说明时，才可以将该技能的实施标记为完成。
