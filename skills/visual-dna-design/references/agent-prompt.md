### 必须实现的设计能力
1. 先审计现有架构、组件、样式、状态、路由与测试，再进行最小范围改造。
2. 根据业务定义 Visual DNA，禁止无条件套用深色左侧栏、四张 KPI 卡、浅蓝灰背景和蓝紫按钮。
3. 工作台内容区占用扣除导航后可用主区域的至少 90%；避免固定 max-width 造成的宽屏大留白。阅读型长文例外，需说明理由。
4. 提供六种可切换布局：编辑式、平衡网格、纵向流程、分析聚焦、Bento 拼贴、左右分栏。
5. 提供六种导航：顶部、左侧、右侧、底部、悬浮、隐藏；支持收起/展开，隐藏时必须保留可访问的唤出按钮。
6. 提供六类配色主题与逐项颜色定制。颜色设置需覆盖背景、面板、文字、边框、强调色和导航，不得只换背景。
7. 提供中英文分开的字体选择与预览。英文选择包括 8 款主字体和 Liberation Sans/Serif 兼容项；中文包括 Noto Sans SC、Noto Serif SC、LXGW WenKai、Smiley Sans、Alibaba PuHuiTi、ZCOOL KuaiLe、YouShe BiaoTiHei、Chiron GoRound TC。
8. 用户设置分别持久化：布局、列宽比例、模块间距、导航位置、收起状态、配色与中英文字体，不得相互串改。
9. 并排卡片自然等高：Grid 使用 stretch，对应模块用 flex column 与 flex:1；禁止无条件 height:100% 撑高卡片；不得裁切真实内容。
10. 中文字体资源必须按许可允许的方式由 Vite/Webpack/CI 构建流程子集化，包含标点、数字和动态 UI 文案。不要让用户在本机执行 PowerShell 或转码脚本。不得把 Arial / Times New Roman 文件打包。若字体资源未部署，必须诚实显示回退提示。

### 实施规则
- 不能用假数据填满页面，不能伪造 API 状态或任务成功结果。
- 不得删除现有功能、数据模型、路由、接口和多平台预览以换取视觉效果。
- 公共 CSS 必须有作用域或命名空间，防止影响冻结页面。
- 用已有主题变量或统一 Token，不把颜色硬编码散落在各组件。
- 主题可以更换，但业务结构与视觉风格应能独立调整。
- 对现有设置存储做兼容与容错；恢复某项设置不应清空其他设置。

### 必须完成的验收
1. 桌面、平板和手机真实渲染检查；至少包括约 1440px、900–1100px、390–430px 的视口。
2. 在宽屏记录 content width / available main canvas width 的比例，目标 ≥ 90%。
3. 在并排卡片的默认空状态和有数据状态测量顶部/底部差值；理想目标为 0px。
4. 实际点击测试六种布局与六种导航，检查隐藏导航、收起/展开、键盘 Esc、focus-visible。
5. 依次更换主题、颜色、字体和布局，然后刷新浏览器，确认选择可恢复。
6. 检查字体网络请求、资源、许可、常用中文、标点、数字覆盖；没有实际字体文件就不得声称自托管完成。
7. 运行项目已有语法、单元、集成、API 与回归测试；确保冻结页面基线没有变化。
8. 在交付中列出修改文件、测试结果、未满足的字体资源依赖、部署 URL 和实际版本。未完成生产部署时不得声称已上线。

执行顺序：审计 → 设计方案 → 实现 → 自动化测试 → 浏览器验收 → 预览部署 → 验证 → 正式发布（仅在项目流程允许时）。
