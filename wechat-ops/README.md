# DAVYLAB 公众号草稿工作流

品牌主张：**把想法，做成能用的工具。**

本目录定义「日常选题 → ChatGPT 生成稿件 → GitHub 交接 → WorkBuddy 浏览器操作公众号后台 → 保存草稿 → 人工复核」流程。

## 安全边界（必须遵守）
- WorkBuddy 只允许在公众号后台创建/编辑内容并保存为**草稿**。
- 严禁点击「发表」「群发」「发布」「立即发布」「定时发布」等对外发布相关按钮。
- 正式发布必须由用户本人在公众号后台手动完成。
- 不绕过登录、验证码、二次验证或平台安全机制；遇到验证或异常立即暂停并报告。
- 不把 Cookie、密码、验证码、AppSecret、访问令牌或其他凭据写入 GitHub。
- 不伪造数据、引用、案例、产品功能或二维码。事实不确定时标注待核实。
- 后台页面变化、目标账号不明确、草稿状态不确定时，停止操作，不猜测。

## 每篇稿件的目录约定
`wechat-ops/drafts/YYYY-MM-DD-short-slug/`

必须包含：
- `article.md`：文章正文。
- `publish.json`：标题、摘要、作者、封面路径、栏目、状态和发布限制。
- `review.md`：事实核查、格式检查和待确认事项。
- `sources.md`：正文来源；无外部来源时明确说明。
- `cover.png`：需要封面时才放入真实封面素材。不能用虚构二维码替代公众号真实二维码。

## 状态流转
`draft-prepared` → `ready-for-workbuddy` → `draft-saved-in-wechat` → `human-reviewed` → `published-by-human`

自动化只允许推进到 `draft-saved-in-wechat`。正式发布只能由用户本人完成。

## 成功标准
1. 目标公众号核对为 DAVYLAB。
2. 标题、摘要、正文和封面与 GitHub 稿件一致。
3. 后台显示草稿已保存，并可重新打开。
4. 未点击任何公开发布/群发按钮。
5. 将操作结果和未解决问题记录到 `review.md` 或运行日志。
